The “You” screen — three design directions

Wireframes, not mocks: grey = content slots, X-boxes = images, everything is about hierarchy and grouping. The current screen is shown for reference. All directions must continue to provide everything in the inventory below — they only differ in where it lives.

Function inventory (must survive any redesign): View profile · Edit profile · Settings · Favourites · Saved posts · (Collections, feature-flagged) · Followers · Following · Blocked accounts · Account switching (other logged-in accounts) · Pending registrations · Add account · Log out

Key moves: the profile card grows up into a mini profile header (banner + big avatar + handle + bio + stat chips) — the tab becomes a place, not a menu; Edit/Settings become toolbar or overflow ("···") since they're visited rarely; destructive stuff (log out) sinks to the bottom quietly.

  • Strongest match with the “You” rename — identity-first
  • Stats give the screen content, not just plumbing
  • Reuses the profile viewer's data model (banner/fields already exist)
  • Needs banner layout + stat formatting (most new SwiftUI)
  • Overflow (“···”) hides Edit/Settings one tap deeper
implementation: medium — one view restructure, no logic changes

Key moves: no scroll at all — a compact identity bar (tap = your profile, gear = settings), a 2×3 tile grid where every destination is one big tap target carrying a live count, account switching as chips/segment, log out demoted to a danger zone or into Settings.

  • Glanceable; counts make the screen feel alive
  • Same tap-depth for everything (flat, no hierarchy)
  • Loves Dynamic Type and thumb reach (tap targets are huge)
  • Counts need data fetches the current screen doesn't do
  • Two-level items (settings → …) get artificial homes
  • Grid of six can feel “app-launcher”, not “network identity”
implementation: medium-high — grid + count plumbing (2 stats calls exist already)

Key moves: keep the list skeleton but change its rhythm — a compact top bar (avatar+name inline; the gear or “···” opens a bottom sheet with Settings · Edit profile · Log out), the four content timelines become a horizontal chip row (scrollable, one tap), accounts become avatar chips instead of rows, Sparse regrouped remainder underneath.

  • Smallest diff from today — reuses rows and navigation as-is
  • Sheet puts rare actions away without hiding content
  • Works with every Dynamic-Type size; best VoiceOver story (linear)
  • Least “wow”; still list-flavoured
  • Bottom sheet for settings is unconventional for tab roots
implementation: low — restyle + one new sheet, zero logic changes

Recommendation

Option A, with one dip into B: the identity-first structure, but keep the four quick-access items as a 2×2 tile row at the top of the content (rather than stacking a second grid) and surface Settings as a top-bar gear instead of burying it in “···” — that removes both cons of A as sketched. It matches the rename (“You” = a place for you), gives the screen live content (stats from the account object, which the profile view already loads), and its layout risk is the same one the existing profile screen already solved. B is the one to revisit if the screen ever grows more destinations (e.g. Collections) — its grid absorbs growth best; C is the fallback if you want ship-today.

All three keep the login-affecting flows exactly where they are today (account switching, pending registrations, add account, log out) — the inventory at the top is the acceptance test for whichever direction wins. Implementation in any case is confined to ProfileMainMenuView.swift (SwiftUI, ~250 lines) — no router, auth, or settings changes needed.
