Collection detail — two whole-page designs

Both pages use the locked Option B member card (inset cover strip, avatar, name, username, truncated bio, follow in the header row). What differs is how the page-level collection info composes above it. Wireframes: grey = slots, X-boxes = images, circled crosses = avatars, dark pill = follow CTA.

Collection info the header carries today (all already on CollectionViewModel): name · “by @author” · description (optional) · account count · conditional “You are featured in this collection / Remove me” callout (kept in both designs, placed under the header).
Member card (fixed): Option B — cover strip inset in card, small overlapping avatar, display name + username, follow right, bio snippet (1–2 lines, truncated) below.

Card note for the two-up variant

Design 2 needs a compact card variant of Option B: cover strip shortened (~36pt), avatar 30pt, name + username only, follow as a full-width mini-button, bio dropped to a single line under the name row (or omitted — grid cards that are all name/follow still read fine as a directory). The full Option B card stays for iPhoneandscape/full-width contexts.

Implementation notes (either design)

- Header replaces the block rendered for case .collection in TimelineListView’s header section (name / by-author / description / count today). All data is on CollectionViewModel; the emoji comes from the same title-splitting helper the Directory rows use.
- “You are featured / Remove me” callout stays, placed directly under the header in both designs (only shown when the viewer is a member).
- Member cards: new card view substituted for AccountRowView on collection timelines; reuses the relationship/follow machinery and the accountRowControl(for:) “remove from collection” control.
- Avatars strip (Design 1): member avatar URLs already exist on the collection view model (used by the avatar mosaic today); cap the strip at ~6 avatars + count chip.
- Grid (Design 2): LazyVGrid columns: 2 fixed with flexible spacing — the timeline list content area already provides a usable width; card width ≈ half minus padding. Nothing in the current TimelineList structure prevents a grid scoped to the collection case.
- Nav title stays empty (current behaviour — the header holds the title), so the large title area is free for both designs.

Recommendation: Design 1 is the safer, more on-brand page — it extends the card system you already have and keeps the full bio. Design 2 wins on browsability but needs a compact card variant and gives up most of the bio. If the collections typically hold 10–30 accounts, 2 helps discovery; if they are smaller and curated, 1 tells the story better.
