Collection account cards — three directions

Wireframes, not mocks: grey = content, X-boxes = images, circles with cross = avatars, dark pill = the follow CTA. Each phone shows two stacked cards to indicate list rhythm. Context: the collection detail screen (a collection tapped from the Directory or You > Collections) — currently a plain list of the avatar / name / username / verified-link / follower-and-post-counts / follow rows.

Every card must contain: avatar · cover photo · display name · username · bio snippet (truncated) · follow button
Drops from the list (still on the full profile): verified links · follower/following/post counts
Data: everything is already on the account entity — cover = header, so no extra API calls. Bio snippet needs the same off-main-actor HTML→text parsing the Directory featured card uses. Bio is parsed at display-prep time, never in the row.

Implementation notes (any direction)

- New view (e.g. DirectoryAccountCard) substituted for AccountRowView in TimelineListView’s .account case when the timeline is a collection detail (viewModel.timeline.collectionViewModel != nil). The “Remove from collection” control and the empty-state for self-removed members flow through the same accountRowControl(for:) path and must keep working — the card takes the same control enum.
- Data: cover = account.header (already on the entity; add an accessor on MastodonAccount if missing). Fall back to a flat surface/gradient when the header is missing — common on Oslo profiles.
- Bio snippet: parsed HTML→text off the main actor in display prep (same helper as DirectoryFeaturedModel), cached on the row model; 1–2 lines, line-limited with ellipsis.
- Follow: unchanged machinery — RelationshipViewModel button + relationship display-prep that already runs for .account items.
- Images: covers load through the existing downsampled pipeline; request ~600 pt width (cards are ≈ full content width) rather than the 1200 pt timeline media size.
- Verified links / counts: dropped from the card only; the profile keeps them. An optional middle ground is a single “1.2k followers” caption in the username row if the directory feels too sparse after using it.

Recommendation: Option A is the strongest realization of “a curated directory of cards”; Option B is the safe, browsable compromise and the quickest to build. If cover photos turn out to be rare in the collection members, A degrades worst — worth a quick eyeball of a real collection before committing to it.
